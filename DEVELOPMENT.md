# Development

Reference for the tools, the dev server, and the tests. Start with [CONTRIBUTING.md](CONTRIBUTING.md); the user reference is in [README.md](README.md).

## Comments and license lines

No comments anywhere in the repo. The only exception is the first-line license comment in each kit file. It names the third-party parts of the file and `THIRD_PARTY_NOTICES`. `go test` checks the line of each kit file and of each `dist/` file (`dist` copies the line of the source file and minifies only the code after it). The files in git have no version; `release.yml` stamps the release copies with `go run ./tools/gen stamp -version X.Y.Z DIR...` (`/*! clanker-ui vX.Y.Z | MIT | ...`):

```text
/*! clanker-ui | MIT | includes shadcn/ui (MIT, shadcn) and Lucide icons (ISC); see THIRD_PARTY_NOTICES */
```

`clanker-ui.js` also names Base UI (ported DOM, state attributes, and logic) and Embla Carousel (the carousel engine is a port):

```text
/*! clanker-ui | MIT | includes shadcn/ui (MIT, shadcn), Base UI (MIT, Material-UI SAS), Embla Carousel (MIT, David Jerleke), and Lucide icons (ISC); see THIRD_PARTY_NOTICES */
```

`clanker-ui.css` (written by `tools/gen`) names the Tailwind CSS and tw-animate-css output, and `clanker-ui-themes.css` names its palette sources:

```text
/*! clanker-ui | MIT | includes shadcn/ui (MIT, shadcn), Tailwind CSS (MIT, Tailwind Labs), tw-animate-css (MIT, Luca Bosin), and Lucide icons (ISC); see THIRD_PARTY_NOTICES */
/*! clanker-ui | MIT | includes shadcn/ui (MIT, shadcn) and editor palettes (MIT; Tokyo Night Apache-2.0); see THIRD_PARTY_NOTICES */
```

When new third-party material comes into a kit file, add its full notice to `THIRD_PARTY_NOTICES`, name it in the license line, and add its copyright line to `TestLicenseNotices` in `banned_test.go`.

## How the minified and group files are made

- Each CSS rule goes to the group of the part that it styles (the subject of the selector; a part attribute such as `data-input-group-button` wins over the slot of the component that it renders). Each top-level statement of `clanker-ui.js` up to `scan(document.documentElement)` goes to the core; after it, `define("<slot>")` and the camelCase prefix of the declared name (`dropdownMenuShow`) select the component, and a statement without a name goes with the statement before it. `tools/gen/groups.tsv` has the component of each group, the "Needs" column, and `js:` name prefixes for helpers (`choice`, `proxy`). A group may use only the core: the run stops when a group uses code of another group. The core exports the helpers that the groups use with a `_` prefix; they are not public API.
- esbuild (Go API, pinned in `go.mod`) minifies. The server binary does not include it.
- `go test` checks that `dist/` is fresh and that two runs give the same bytes, that the group files in group order give `clanker-ui.min.css`, that the group order changes the order of no two rules that set the same property on the same part with the same specificity, that the JS statements of the groups give `clanker-ui.js` again, that esbuild links all modules without a missing export, and that the public exports are the same. `test/split_test.py` loads `test/split/<group>.html` (only the core, the group, and its needs) and compares the attributes and computed styles of every element with the same page on the readable files, and does one interaction for each group. In WebKit it compares the styles of rendered elements only: after a load from the cache, WebKit can report stale computed styles in a `display: none` subtree ([#2](https://github.com/bl4ko/clanker-ui/issues/2)); the styles are correct when the element renders.

## Docs site

The server also renders a docs site with the layout and behavior of ui.shadcn.com: header, sidebar, one page per component, On This Page, search, Copy Page, and prev/next. Go `html/template` and a small Markdown renderer build every page from `docs/` on the server. The browser loads full pages; there is no client-side rendering.

| Route | Content |
| --- | --- |
| `/` | Home page. |
| `/docs`, `/docs/<path>` | Page from `docs/content/<path>/page.md`. `/docs` is `docs/content/index/page.md`. A `docs/nav.json` link without a `page.md` gets a generated page (see below). |
| `/docs/<path>.md` | The page as Markdown: front matter, then the body with each example as an `html` (and `js`) code fence. Copy Page copies this text. Every docs page links it with `<link rel="alternate" type="text/markdown">`, and every page links `/llms.txt` with `<link rel="describedby">`. |
| `/llms.txt`, `/llms-full.txt`, `/clanker-ui.json`, `/clanker-ui.schema.json`, `/skills/clanker-ui/...` | The same files as on GitHub Pages (`exportExtras` in `export.go`). |
| `/view/<example>` | One example on a bare page. Only this route sends `frame-ancestors 'self'`, so the site can frame it. |
| `/assets/<hash>/<file>` | Kit files, `docs/assets/*`, and example modules. `<hash>` is one hash over all of them, so relative imports (`./clanker-ui.js`) load one copy. `Cache-Control: public, max-age=31536000, immutable`. A different hash (a page from an older release) gets the current file with `no-cache`. With `DIR=.`, any hash works and `Cache-Control` is `no-store`. |
| `/demo` | The one-page component demo (`demo/index.html`). |
| A `docs/nav.json` link without a page | A page generated in `pages.go` from the existing sources, in the order of a shadcn page: the first example, Installation, Usage, Examples, API Reference, and Keyboard and Accessibility. A component page (the catalog `docs` URL selects it) uses the catalog entry and the `## Full text` of its skill file (`skills/clanker-ui/references/components/<name>.md`). Other pages use the README section of the item `readme` anchor (from `docs/llms-full.txt`, up to the next heading of the same level or the next anchor of another page). The examples are the blocks of the demo section with the same id (`docSections` maps other pages, for example `chart` to the chart sections); the page holds them in `<div data-docs="content" id="<section>">` and loads `demo/demo.css` and `demo/demo.js` from `/assets/<hash>/`, so the previews are live. `demo.js` skips the sections that are not on the page. |
| `/docs/components/typography` | 301 to `/docs/typography` (`docRedirects` in `docs.go`; the query is kept), as ui.shadcn.com sends `/docs/components/base/typography` to `/docs/typeset`. The Components list keeps the old link. Redirects send `Cache-Control: no-cache`. |

HTML and Markdown responses have `Cache-Control: no-cache` and an `ETag`. Text responses (HTML, Markdown, CSS, JavaScript, SVG) are gzip-compressed when the request accepts `gzip` (`Vary: Accept-Encoding`, ETag with a `-gz` suffix; compressed bytes are cached). With `DIR=.`, the server loads `docs/` again only when a file changes (size or modification time). Files and folders in `docs/content` whose names start with `.` or `_` are ignored.

### Example classes

The examples in `docs/content/**/examples/*.html` may use the Tailwind classes of the shadcn examples for their layout (`w-full max-w-sm`, `flex gap-2`, `rounded-lg bg-muted`). `docs/assets/examples.css` has their rules, and every docs page loads it after `docs.css`; the kit files do not have them. After a class change, run (Tailwind CLI as in Generated CSS):

```sh
go run ./tools/gen utilities -src "$SHADCN_SRC" -content 'docs/content/**/examples/*.{html,js}' -out docs/assets/examples.css
```

`go test` fails when a class of an example has no rule; CI makes the file again and fails when it differs.

### Docs coverage

`tools/gen/docs-shadcn.tsv` lists every shadcn docs page and live example (`<ComponentPreview name styleName>`) of the pinned `apps/v4/content/docs/{components,ai-elements}/base`, `utils`, `forms`, and `dark-mode` files, in shadcn order. `tools/gen/docs-map.tsv` has one reviewed row for each: `<shadcn item><TAB><ours>[<TAB><reason>]`. A page row names a `docs/nav.json` link; an example row names an example on that page (a `docs/content/**/examples/<name>.html` file or a generated `demo-<section>-<n>`). `-` needs a reason; `?` is a row to review.

```sh
go run ./tools/gen docs-coverage -v
go run ./tools/gen docs-coverage -src "$SHADCN_SRC"
go run ./tools/gen docs-coverage -src "$SHADCN_SRC" -write
```

The first command prints the totals, the mapped examples whose `styleName` is not the style of our example (its `style=` in `page.md`, else the `style` of the page in `docs/nav.json`, else `base-nova`), and (`-v`) the items without a match. `-src` also checks `docs-shadcn.tsv` against the pinned files (CI does this); `-write` writes it and adds a `?` row for each new item. `go test` fails when an item has no row, a row has no item, the rows are out of order, or a target does not exist on the mapped page.

### Add a page

1. Find the link in `docs/nav.json`. Every kit page has a link there already.
2. Write `docs/content/<path>/page.md`. Start with front matter (`title` and `description`, nothing else), then the body:

   ````md
   ---
   title: Button
   description: Displays a button or a component that looks like a button.
   ---

   {{example "button-demo"}}

   ## Usage

   ```html
   <button type="button" data-slot="button">Button</button>
   ```
   ````

3. Put each example in `docs/content/<path>/examples/<name>.html`. An optional `<name>.js` is an ES module that loads on every page that shows the example; it imports the kit as `./clanker-ui.js`. Names are unique across the site and use the shadcn registry names: `<component>-<example>` (`button-size`). An example for a page that is not ported yet can live in that page's folder without a `page.md`.
4. Copy the Button page for a component: main demo, Installation (one line), Usage, kit notes, one `##` per shadcn example (same names and order) with its preview, RTL, API Reference (attribute, part, state, and event tables from this README).

Content rules:

- Markdown subset: headings `##` to `####` (`##` and `###` go to On This Page; the id is the text in lower case with `-` for spaces), paragraphs, `-` and `1.` lists (nest with indent), tables (`\|` for a pipe in a cell), `>` quotes, `---`, inline code, links, `*em*`, `**strong**`, and code fences with a language and an optional `title="file"`. Raw HTML shows as text. Links go to `/...`, `#...`, a relative path, `https://`, or `mailto:`.
- Tags, each on its own line: `{{example "name"}}` (options: `align="start|center|end"`, `height="auto"`, `style="<style>"` and `scheme="<scheme>"` to override the page `style` and `scheme` of `docs/nav.json`), `{{components}}` and `{{components "new"}}` (link grid of the Components group).
- The server highlights `html`, `css`, `js`, `json`, and `sh` (also `bash`, `shell`) code with `tk-*` classes. `docs/assets/docs.css` has the colors (4.5:1 or more on the code background). Other languages are plain text.
- Examples follow the kit rules: no inline scripts or styles, no `style=""`, no comments. Layout classes for examples (docs only, not in the kit, like the Tailwind classes in the shadcn examples) are the Tailwind names in the `[data-docs="preview"]` block of `docs.css`, for example `flex`, `gap-4`, `max-w-sm`, `text-sm`, `text-muted-foreground`, `whitespace-pre-wrap`, `animate-spin`, `sm:flex-row`, and `rtl:rotate-180`; inline sides use the logical names (`ms-auto` for `ml-auto`). Add a class to `docs.css` when an example needs a new one.
- `docs/nav.json`: `header` (main nav and the search group "Pages"), `sections` (desktop "Sections"; prefix match for `data-active`, except `/docs`), `mobileSections`, and `groups` (sidebar, mobile menu, search, and the prev/next order). Item fields: `title`, `href`, `new` (blue dot), `hidden` (only in the prev/next order), `mobileOnly` (not in the desktop sidebar), `readme` (README heading anchor of a page without `page.md`), `description` (the description of such a page; else the demo section description or the first README paragraph), `style` (the kit style of the page previews, like the shadcn `styleName`; Nova when absent), and `scheme` (a `data-scheme` of `clanker-ui-themes.css` on each preview, like the shadcn `previewClassName` `theme-blue`).
- A preview in another style keeps the docs chrome in Nova. The server makes `style-<name>.css` from `clanker-ui-<name>.css` and `examples.css`: every layer of the style is put in `@scope ([data-docs-style="<name>"])` inside the layer `clanker-docs-<name>`, after a `reset` layer that sets `all: revert` (except on `svg` and its children: `revert` drops presentation attributes such as `fill`, `stroke`, and `d`) and every custom property of the Nova component layers to `revert` in the scope. So in a preview only the style rules apply, as if the page loaded only that style. Tokens that the style has and Nova does not are set on the preview. The page loads the file (and the themes file for a scheme) only when one of its previews uses it. Limit: a Nova `!important` declaration still wins in the preview (button-group end radius, command radius).
- `go test` loads all content and fails on an unknown or unused example, a bad tag, a page without a `docs/nav.json` link, a file that is not `page.md` or an example, a nav link that does not return 200 (a `docRedirects` source must return 301 to its target, and the target 200) or starts with `//`, a page with more than one active Sections item, a link inside link text, a rendered page with a duplicate id, a link that does not resolve, or a problem from the HTML security scanner. `FuzzHighlight` checks that the highlighter ends and keeps the text for any input.
- `docs.css` styles only the site shell and the prose of the page. It does not change kit components: prose rules skip everything in `[data-docs="preview"]`, and a preview starts again at `font-size: 1rem` and `line-height: 1.5`, like an app body. `check_docs_preview_keeps_kit_styles` loads `docs.css` into the demo and requires zero computed-style changes on kit parts. Prose text is 18.9 px below 640 px, 16.875 px from 640 to 767 px, and 15 px from 768 px (as on ui.shadcn.com). Code is 14 px with a 24.5 px line height; example code shows line numbers (`--code-number`, not copied).

Behavior:

- `docs-sidebar.js` is a classic script in `<head>`. A `MutationObserver` restores the sidebar scroll while the sidebar is parsed, before the first paint. It keeps `sessionStorage["docs-sidebar-scroll"]` (`{ pathname, scrollTop }`) up to date on scroll. On a new page it applies the stored offset and then centers the active item if it is out of view (longest `href`, then nearest to the center). shadcn keeps the sidebar mounted across client-side navigations; full page loads get the same result this way.
- `docs.js` (module): ⌘K, Ctrl+K, or `/` (not in a text field) toggles the search dialog (kit `command` in a `dialog`, items are links); On This Page marks the heading in the top 20 % of the viewport (`IntersectionObserver`, `rootMargin: "0% 0% -80% 0%"`); Copy Page writes the `.md` text to the clipboard (fetched on hover or focus, `ClipboardItem` with a promise while it loads) and shows a check for 2 s; View Code opens the code (kit `collapsible`, no animation) and focuses it; a pointer move over, pointer down on, or focus on a same-origin link adds `<link rel="prefetch">` once (a page that loads under a still pointer starts no request; Chromium and Firefox use it, Safari ignores it).
- Header: main nav from 1024 px, else the "Menu" button that opens a full-screen kit `popover` (blurred `--background` at 90 %). Search button from 768 px. GitHub link and the kit [theme toggle](README.md#theme-toggle-and-switch) (`data-theme-set="toggle"`, `contrast` icon, `aria-keyshortcuts="D"`). The page has `<meta name="theme-color">`; `clanker-ui-theme.js` sets it before the first paint. Sidebar from 1024 px (288 px), On This Page from 1280 px (288 px), article 640 px.

## CI

`tools/ci/plan.py` reads the changed files of a pull request and writes the browser matrix. `go`, `gitleaks`, and `ci-result` always run. CI does not run on a push to `main`: the `main` ruleset requires a pull request that is up to date with `main` and green, so the merged commit is the tested commit. `ci-result` passes when every job passed or was skipped.

| Change | Browser jobs |
| --- | --- |
| Nightly run, `workflow_dispatch` (release check), or label `full-ci` | All: Chromium, Firefox, and WebKit in light and dark, `--rtl`, `--reduced-motion`, the minified kit, and the exported pages. |
| Kit, generator, server, `test/run.py`, `ci.yml`, `tools/ci/plan.py`, or any other file | Pull request tier: Chromium and Firefox in light and dark, WebKit light (5 macOS jobs), a minified-kit smoke set, and the exported pages. |
| Only component files: lines of `clanker-ui.js`, `clanker-ui.css`, or `tools/gen/kit.css` that belong to a component, the other kit files, `docs/content/`, `docs/assets/`, `docs/nav.json`, `docs/templates/`, `demo/` (with `dist/`, test modules, Go test files, and docs) | The pull request tier, only the checks that ran the changed code or showed the changed component in the last measured run (`tools/ci/impact.tsv`), and checks that are not in the file. A kit file change keeps all 5 WebKit jobs (the map has no WebKit measurement). The minified-kit smoke set keeps `foundation` and the selected rest. The exported pages run as two jobs, light and dark. Core JS, tokens, base CSS, utilities, an unmeasured file, and a map that was measured on other tests, demo, or kit files count as "any other file". |
| Only `test/<module>_test.py`, `test/behavior/`, `test/split/`, `test/spike/`, `test/lint/`, or `skills/clanker-ui/references/design-lint.js` (Go test files and docs can be in the same change) | The pull request tier, only for the changed modules. `test/lint/` and `design-lint.js` run the `lint` and `pages` modules. |
| Only Markdown, `docs/*.txt`, `skills/`, licenses, issue templates, `release.yml`, `pages.yml`, or `renovate.json` | Only the exported pages in Chromium. |
| Only Go test files (`*_test.go`) | None. |

Browser jobs run `test/run.py --retry`, and on a pull request also `--exitfirst`: the job stops at the first check that fails twice. The step summary lists the checks that passed on retry.

The `go` job also runs `test/run.py --self-test` and makes `clanker-ui.css` again from the pinned inputs (`tools/gen fetch`, then `tools/gen -out clanker-ui.css`). It fails when the file differs, so a hand edit of `clanker-ui.css` cannot merge.

`python3 -I tools/ci/plan.py --self-test` checks that each check runs once in each tier. The `go` job runs it.

`tools/ci/impact.py` maps a change to keys. A JS line maps to its top-level statement (split and named as in `tools/gen dist`): a statement with functions needs the checks that ran it; a data statement (`const x = new Map()`) needs the checks that ran the statements that use it. A statement that no check ran falls back to its component. A CSS line maps to the `data-slot` components of its rule (all of them must be shown), a docs file to its page. `tools/ci/impact.tsv` lists, for groups of checks, the keys that they touched: statements that ran (Chromium coverage, load time included), rendered `data-slot` elements (outside `[hidden]`), and the fetched files and pages. `test/run.py --impact` prints these lines; it changes no result. The first line of the file has a hash of `test/`, `demo/`, and the kit files of the measured commit. When the base of a pull request has other files, the plan uses the pull request tier. Refresh the file after a change of these files: run the pull request tier with `--impact`, then `python3 -I tools/ci/impact.py build tools/ci/impact.tsv <measured commit> <log directories>`. To plan a local pull request run, set `EVENT=pull_request` and `PLAN_BASE=<base commit>` and pass the changed files.

`plan.py` splits each engine, theme, and mode into jobs of about equal time. `tools/ci/durations.tsv` gives the seconds of each check from a full run; a check that is not in the file gets the median. The file changes only the split, not the checks that run. `shards()` splits a matrix again into a given number of runner jobs with the same split code; `test/run.py --self-test` checks that `plan.py` finds the same checks as the runner.

## Demo and tests

```sh
ADDR=127.0.0.1:8110 go run .
uv run --no-project --with playwright playwright install chromium firefox webkit
uv run --no-project --with playwright python -I test/run.py --base-url http://127.0.0.1:8110 --out out/run
go run ./tools/gen dist
go vet ./... && go test ./...
```

- Run `go run ./tools/gen dist` after every change of a kit file; `go test` fails when `dist/` is old. On a merge conflict in `dist/`, take either side, then run `go run ./tools/gen dist` again.
- Docs site: `go run . -export site -base /clanker-ui -site-url https://bl4ko.github.io/clanker-ui/` writes the static GitHub Pages site to the new directory `site/` (CSP in a meta tag, without `frame-ancestors`); use `-base /` for a custom domain. `sitemap.xml` lists the home page, the demo, and every docs page. There is no `robots.txt`: crawlers read it only at the host root. `test/pages_test.py` checks it when you serve the parent of the export directory and set `--base-url http://127.0.0.1:<port>/clanker-ui`.
- The server embeds the kit, `dist/`, `demo/`, `docs/`, and `skills/clanker-ui/`. It serves `dist/` files at their file name (`/clanker-ui-core.min.js`). `-kit min` (or `KIT=min`) answers the readable kit names with the `dist/` files: `clanker-ui.css` with `clanker-ui.min.css` (also themes and a11y), and `clanker-ui.js` and `clanker-ui-chart.js` with a module that exports the minified modules. Then `/demo`, the docs, and `test/run.py` run on the minified kit. `-dir .` (or `DIR=.`) serves from disk so edits show without a rebuild (pages are rendered again on each request). `ADDR` sets the listen address (default `:8080`). `/healthz` returns 204. Every response has the CSP above, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Cross-Origin-Opener-Policy: same-origin`.
- `test/run.py` starts nothing. It loads `/demo` from `--base-url` (or the path in the test file's `START`, for example `START = "/docs/components/button"` in `test/docs_test.py`) and runs every `check_*` function in `test/*_test.py` in Chromium, Firefox, and WebKit, in light and dark, at 1280 and 390 px. A fresh browser context is used for each check. A check fails on any console error or warning, page error, window `error` event, failed request, HTTP status 400 or more, or CSP / Trusted Types violation, also when it skips after them. Browsers do not log some window `error` events to the console (for example "ResizeObserver loop completed with undelivered notifications"), so an init script records them. Options: `--only g1`, `-k regex`, `--engines`, `--themes`, `--widths`, `--out` (default `clanker-ui-run` in the system temp directory), `--reduced-motion`, `--rtl` (sets `dir="rtl"` on `<html>`), `--headed`, `--jobs N` (up to N engines in parallel, one process each; the output is the same, the summary covers all engines), `--retry` (a failed check runs once more at once; a pass then prints `flaky [...]` and counts as pass), `--exitfirst` (stop after the first failure), `--list` (print the selected `module.check` names and their count, no browser), `--self-test` (test the runner and the behavior comparison `E.compare` without a browser, in less than a second), `--shots`. A failure saves `<out>/<engine>/<theme>-<width>/<file>/<check>-failure.png`. A pass saves no screenshot; `--shots` also saves `t.shot` images and a section shot at the end of each check. Each `ok` and `skip` line shows the seconds of the check (a `FAIL` block ends with `took N s`); the summary lists the 10 slowest checks. The `FAIL [engine theme width] module.check` line keeps its format, because CI reads it. With `GITHUB_ACTIONS` set, each failure also prints an `::error` annotation and each flaky check a `::warning`.
- Dark runs use the system color scheme (`prefers-color-scheme`). Firefox gets the preference `layout.css.prefers-color-scheme.content-override` because Playwright's color-scheme emulation does not reach Firefox, and `privacy.bounceTrackingProtection.mode = 0`, because Firefox Nightly starts to log a "bounce tracker" warning for `127.0.0.1` on every page in long runs.
- Every page sees the date 2026-10-28 (`Date` without arguments and `Date.now()`, local noon at load; time keeps running), so date checks do not depend on the real date.
- WebKit quirks the runner removes, in WebKit only, and only when the violation has no source file (`?`) or a `web-inspector://` source: Playwright's screenshot inserts a `<style>` element (`style-src-elem`); every `<select>` reports a `style-src-attr` violation for its internal shadow tree (target `<select>`, or the document when a script-created select is no longer in the page; document reports are bounded by the number of `<select>` elements created by script). Each removed violation also removes one matching "Refused to apply a stylesheet" console error. A violation with a script source, such as kit code that sets a style attribute on a `<select>`, still fails. Safari 27.2 (WebKit bug 327212) reports it too, for static and script-made selects; no visual effect unless text-overflow is set; h() makes selects in an inert document to avoid it (remove when Safari ships 324283@main). The runner also drops, in WebKit only, the console warning "This document is not cross-origin isolated ... SharedArrayBuffer is unavailable" when it has no source: the WebKit build of Playwright 1.65 (WebKit 27.2) logs it for the second and each later page load in a tab, also for a stylesheet as the document and with JavaScript off. The same warning with a script source still fails.
- Each `assert` gets a message when the runner loads the test file: its source, for one comparison the two values, and then its own message (a tuple or a variable prints its value). Failures print the test file and line. `t.settle()` fails with the animations that still run (name, part, current and end time).
- Firefox runs a microtask that a listener queues during a Playwright key press only after all key listeners and a layout flush. A check that needs microtask timing runs only its mouse steps in Firefox.
- Engine facts that checks must not take as kit faults (Playwright 1.65: Chromium 158, Firefox 159, WebKit 27.2). Chromium 158 reports `flex-start` and `flex-end` as `flow-start` and `flow-end` in computed styles; compare with the computed value of a probe element. Firefox 159 handles F6 itself (the focused element loses focus) on a page without the kit; compare with a native page. In about half of the Tab walks into an iframe in a modal `<dialog>` without the kit, Firefox 159 stops on the iframe document first; `g2.overlay_tab_native` drops that stop in Firefox. An element screenshot at a part-pixel scroll offset can be 1 px taller than the element in Firefox 159 and then shows the first row of the element below; keep a gap between elements that are compared by screenshot.
- The demo page (`/demo`) is `demo/index.html` with `demo/demo.css` and `demo/demo.js`. Sidebar links jump at once (no smooth scroll), and every section title stops 144 px (9rem) below the top of the viewport. The current link has weight 600 and a 2 px `--primary` bar at the inline start; hover shows only the accent background. When the current link changes, the sidebar scrolls to keep it at least 48 px inside its edge. `go test` checks that every nav link has a target, that every embedded file is served with its content type, and the security rules above (a small quote-aware scanner reads the HTML attributes).

### Generated CSS

`tools/gen` makes the component CSS from the shadcn source (Base UI base, Nova style) for each base component in `tools/gen/groups.tsv` (64). The method is the one of [Basecoat](https://basecoatui.com) (MIT, also a reference for native-HTML parts), but from the shadcn source. One command writes the final kit stylesheet:

```sh
go run ./tools/gen fetch -src "$SHADCN_SRC"
go run ./tools/gen -src "$SHADCN_SRC" -out clanker-ui.css -tailwind "$TAILWIND"
```

- Styles: `kitStyles` in `tools/gen/main.go` lists the ported shadcn styles (`apps/v4/registry/styles/style-<name>.css`); the first is the default. `-out clanker-ui.css` writes `clanker-ui.css` (Nova) and then one file per other style next to it (`clanker-ui-rhea.css`, `clanker-ui-luma.css`, ...), each with the same parts and `kit.css`, then `dist` (`clanker-ui-<style>.min.css` and group files). `-style <name>` writes only that style. A pinned style that is not in `kitStyles` gets an `upstream style not ported` note. To port one: add `{name, file}` to `kitStyles` and the name to `kitStyleNames` in `main.go` (server and export), and run the generator.
- The generator needs the Tailwind CSS CLI of the version in `tailwindVersion` (`tools/gen/main.go`). Homebrew gives only the newest version, so download the standalone binary `tailwindcss-<os>-<arch>` of that version from the [Tailwind CSS releases](https://github.com/tailwindlabs/tailwindcss/releases) and pass `-tailwind PATH` (default: `tailwindcss` on `PATH`). Another version stops the run with this hint. The same version is `TAILWIND_VERSION` in `.github/workflows/ci.yml` (with the SHA-256 of the Linux binary) and in `THIRD_PARTY_NOTICES`; `go test` fails when they differ. To move it, change all of them and run the generator again.

- `fetch` downloads the pinned inputs with `curl` (HTTPS only) into a new empty directory: `apps/v4/registry/bases/base/ui/*.tsx`, the docs `.mdx` files of Docs coverage, `apps/v4/registry/styles/style-*.css`, `apps/v4/registry/themes.ts`, `apps/v4/app/globals.css`, `packages/shadcn/src/tailwind.css` (all at the commit in `shadcnSHA`), and `tw-animate-css` from npm (version and SHA-512 pinned). It stops when the GitHub tree is truncated, when a file does not have the git blob hash of the tree, or when the tree does not agree with `tools/gen/pin.tsv`. It writes `manifest.tsv` (path, blob hash, size). Use only a directory that `fetch` made: other files in `ui/` that are not `.tsx` are ignored, but an older download without `tw-animate-css.tgz` stops with the `fetch` hint. To move the pin: change `shadcnSHA`, run `fetch -write-pin`, and review the diff of `pin.tsv`. A pinned component that is not in `tools/gen/groups.tsv` gets no CSS and an `upstream component not ported` note, so a pin move does not need a port. To port it, add the JS, the README section, and the catalog example, then a `<component><TAB><group>` line in `groups.tsv`; a `dist` error `data-slot "x" has no component in groups.tsv` names the same fix.
- Each run checks every input file against `tools/gen/pin.tsv` (git blob SHA-1) and the tw-animate-css tarball against its SHA-512. After the check it uses only the bytes in memory. A `.tsx` file that is not in the pin stops the run.
- Downloads are data. Tailwind runs JavaScript from `@plugin` and `@config`. Thus the generator checks all CSS that goes to Tailwind (inputs, `kit.css`, and the full Tailwind input) with an allow-list and stops with `unsafe input: <file>:<line>: ...`. Allowed: custom properties, plain rules, and `@theme`, `@custom-variant`, `@utility`, `@variant`, `@apply`, `@slot`, `@property`, `@keyframes`, `@layer`, `@media`, `@supports`, `@container`, `@starting-style`. Rejected: `@plugin`, `@config`, `@source`, `@reference`, every `@import` that the generator does not write itself, escaped at-rule names, hex escapes outside strings, and `url()` that is not a `data:` URI or a `#fragment`. Token and theme values must not have `{`, `}`, `;`, `@`, `\`, `<`, `>`, or comments. Class names must not have `{`, `}`, `;`, or comments.
- Default tokens are the `neutral` theme of shadcn `themes.ts` (what `shadcn init` installs), light and dark. The `@theme inline` mappings come from `globals.css`. A mapping to a token that `neutral` does not have (`--color-surface`) is not written.
- `-out` is the CSS file (default `out/gen/clanker-ui.generated.css`). `-notes` is the notes file (default `out/gen/<name>.notes.txt`). Standard output is one line: the CSS file, its size, the part and note counts (with the `unmapped construct` count), and the notes file. `-kit` (default `tools/gen/kit.css`) is hand-written kit-only CSS (chart, theme toggle extras); it is used only when `-out` is set (`-kit ""` turns it off), so `go run ./tools/gen -src DIR` writes only the generated CSS. When the file exists, the generator checks it with the same allow-list, prints `kit CSS appended: ...`, and writes the generated CSS, a new line, and `kit.css` as it is. `kit.css` is plain CSS without comments and without Tailwind at-rules (`@apply`, `@theme`, ...). Every rule is in `@layer clanker.tokens`, `clanker.themes`, `clanker.base`, `clanker.components`, or `clanker.utilities`; only `@property` and `@keyframes` stay outside. Another rule or layer stops the run. A generated rule outside a layer moves into `@layer clanker.utilities` (or is dropped when that layer has the same rule; the notes file lists it), and the run stops when one stays. `go test` checks that `clanker-ui.css` has no such rule and that it ends with a new line and `kit.css`. The first line of the output is the license line (shadcn/ui, Tailwind CSS, tw-animate-css, Lucide; full texts in `THIRD_PARTY_NOTICES`), the second line the layer order `@layer properties, clanker.tokens, clanker.themes, clanker.base, clanker.components, clanker.utilities;` (`clanker-ui-themes.css` and `clanker-ui-a11y.css` use `clanker.themes`). Two runs give the same bytes.
- The generator reads each part (`data-slot`, its classes, its `cva` variants, `useRender` state), replaces each `cn-*` marker with its Nova rule, and writes one rule per part: `[data-slot="button"]`, `[data-slot="button"]:where([data-variant="outline"])`, and so on. A missing `data-variant` or `data-size` is the default value. Named groups and peers (`group/field`) select the `data-slot` of the element that has them. An unnamed `group-*` or `peer-*` variant selects only the `group` or `peer` parts of its own component when that component has one (sidebar); otherwise it selects every part with the class, like Tailwind (label). It removes conflicting classes like `tailwind-merge`, with the CSS property that Tailwind gives each class (an important class and a normal class do not conflict; the order of modifiers does not matter, except arbitrary and order-sensitive ones). It maps physical classes to logical ones like the shadcn `rtl` option (`ml-auto` to `ms-auto`). Dark variants match `[data-theme="dark"]`, or `prefers-color-scheme: dark` without `[data-theme="light"]`. `rtl:` and `ltr:` (and the `[dir=rtl]` selectors of the shadcn utilities) match `:dir()` only, so an LTR area in an RTL page stays LTR. The base layer hides closed `<dialog>` and `[popover]` elements that have a `data-slot` (`display: none !important`); other popovers keep the browser default. It also gives every `<dialog>` the values of a `<div>` (auto size and inset, no maximum size, transparent background, inherited text color), because the kit renders a Base UI `<div>` (the dialog, alert dialog, and sheet popup, and the drawer viewport) as a `<dialog>`. Only a plain `<form>` (without a `data-slot`) in a dialog content is `display: contents`. The utilities layer has the markup classes `.sr-only`, `.shimmer`, `.shimmer-once`, `.shimmer-reverse`, and `.shimmer-none`. Kit buttons set `data-variant` and `data-size`, shadcn buttons do not; so `has-data-[variant=ghost]` and `has-data-[size=sm]` select only the parts that set the attribute in shadcn (`bubble`, `item`, ...), not buttons.
- Conditional classes become attribute conditions. A prop compared with a value (`variant === "floating" ? "p-2" : ""`) selects the attribute that holds the prop, also on an ancestor part (`[data-slot="sidebar"][data-variant="floating"] *`). A boolean prop (`showOnHover && "..."`) selects `data-show-on-hover`. A prop in the `classNames` object of a component (`captionLayout === "label"`) selects `data-<prop>` on the component root (`[data-slot="calendar"][data-caption-layout="dropdown"]`; a missing attribute is the default). A prop read as `props.<name>` selects `data-<name>` on the component root (`props.showWeekNumber`: `[data-slot="calendar"][data-show-week-number]`). A value from a context hook (`orientation` from `useCarousel()`) selects the component root (`[data-slot="carousel"][data-orientation="vertical"] *`). Any other identifier makes the condition false and gets an `unmapped construct` note.
- A part that shadcn renders as another component (`InputGroupButton` renders `Button`) keeps the `data-slot` of that component and gets the part attribute (`data-input-group-button`), as in `Parts that are other components`. A variant that a part passes on with `{...props}` and does not set itself stays free: `<button data-slot="alert-dialog-action" data-variant="destructive">` is red, like `<AlertDialogAction variant="destructive">`. A prop with a fallback (`variant={variant ?? "ghost"}`) is also free, with the fallback as its default. A part that renders another component under its own `data-slot` (`MenubarSubTrigger` renders `DropdownMenuSubTrigger` as `menubar-sub-trigger`) also gets the rules of that component's child elements (the sub-menu chevron).
- An attribute that shadcn always renders (`data-size="default"` on a card) also matches when it is missing, but only in a compound selector of that part.
- `tools/gen/map.tsv` is the one list of hand selectors for elements without a `data-slot` (Base UI icons, indicators, positioners, the calendar `classNames`). A line is `<component>/<Function>[/<Tag>[#n]]`, a tab, and a selector; `&` is the root part of the function; `-` writes no CSS (Base UI positioners: the kit uses top-layer popups; chart internals: the kit has its own chart). Keys `<component>/<Function>/components.<Name>/<Tag>[#n]` select the elements of the render functions in a `components={{ ... }}` prop (calendar `Chevron`, `WeekNumber`). Keys `<component>/<Function>/<name>ClassName` select the element of another class prop (`input-otp/InputOTP/containerClassName` is the `[data-slot="input-otp"]` container; its `className` goes to the `input`). The shadcn transform replaces `cn-*` markers only in `className` and in `cva`, so a marker in such a prop or in `classNames` gets no Nova rule, like the installed file and the docs page (input-otp has no `gap-2`; the calendar dropdown root has no border and its caption label no `h-6 pl-1.5 pr-1`). A `cva` call in these props keeps its Nova rules. A part that a `data-[slot=X]:` variant renames (`<FieldGroup data-slot="checkbox-group">`) also matches `[data-slot="X"]`, so `checkbox-group` keeps the field-group look. A key `<component>/cva.<name>` writes the base classes of a `cva` function for another part (`navigation-menu/cva.navigationMenuTriggerStyle`: `[data-slot="navigation-menu-link"][data-variant="trigger"]`, a link with the trigger look). A part that a component renders as an instance with its own classes selects its nearest ancestor with a `data-slot` (`:where([data-slot="command-input-wrapper"]) > [data-slot="input-group"]`); it is a child selector when it is a direct child (`:where([data-slot="trace-collapsible-trigger"]) > [data-slot="trace-icon"]`). A `#n` key (the nth element with that tag) has a third column, a fingerprint of the element (tag, every attribute, and the `className` expression with its `cn-*` markers). The run stops when a fingerprint does not agree (upstream changed the element order or its classes) or when a key matches no element.
- `sourceFixes` in `tools/gen/main.go` repairs broken shadcn classes (`data-activation-direction=left:` to `data-[activation-direction=left]:`). `ignoredMarkers` lists the `cn-*` markers that have no Nova rule and the class that replaces each (none, or `rtl:rotate-180` for `cn-rtl-flip`). The notes file lists each fix. A run of all components (no `-components`) stops when a source fix or an ignored marker matches nothing at the pin: `source fix N (...) matched nothing at shadcn <sha>; remove it from tools/gen/main.go`.
- The output has no `color-mix()` or `@property` fallbacks (all target browsers support both). It is readable, one declaration on each line; only `dist/` is minified. The notes file lists each class or element that the generator could not map, and each selector with a class that kit markup does not set (`[data-slot="card-header"].border-b`). React-day-picker classes in selectors (`.rdp-button_next`) become the `calendar/Calendar/classNames.<name>` selector of `map.tsv`. `[&_.recharts-*]` classes are dropped (the kit has its own chart).
- The last step (`tools/gen/optimize.go`) makes the output smaller and must not change a computed style. It merges rules with the same selector, and `@media`, `@supports`, and `@container` blocks with the same condition and the same parts, only when no rule between them can set a related property on the same element with the same specificity (also in the order of the group files in `dist/`; `kit.css` is part of the proof and is not changed). It drops repeated declarations and the `@property` rules of variables that have no definition and no read. It does not change a declaration: each `--tw-*` definition and each `var(--tw-*)` read stays, because a Tailwind utility on a kit part composes with them (`shadow-md` on a part with a kit ring shows the ring and the shadow).
- `tools/gen/guard` is the check for a change of this step or of the generator model that must not change the look. It loads the old and the new CSS of each style into the same page, switches between them, and compares every computed property (and every custom property that the CSS defines) of every element and of `::before`, `::after`, `::marker`, `::placeholder`, `::selection`, `::backdrop`, and `::file-selector-button`: on `/demo`, every `/view/<example>` page, and every block, in light and dark, at 1280 and 390 px, then with each state attribute of the kit selectors set and removed, with app token values, with unlayered app CSS, with forced `:hover`, `:active`, and `:focus-visible` (Chromium, DevTools protocol; real focus, hover, and mouse press in Firefox and WebKit), and after a click on each trigger. A state attribute test reads the part of the page that the selectors of that attribute can change. No transition runs during a read, and a difference counts only when a second read of the same state, after a full style recompute, shows it again (Chromium can report an old used value of an `auto` margin after an attribute change). `@keyframes` text and the declarations of each `::selection` selector must be equal. `OLD` is a checkout of the commit to compare with:

  ```sh
  uv run --no-project --with playwright python -I tools/gen/guard/guard.py --old "$OLD" --base-url http://127.0.0.1:8110 --tier 2
  ```

  Options: `--browser firefox|webkit`, `--min` (the minified files), `--groups` (the six group files in load order), `--docs --old-url URL` (the docs pages; `URL` is a server of the old checkout, for the scoped `style-<name>.css` files), `--pages REGEX`, `--styles`, `--shard i/n`, `--skip N`, `--tier 0|1|2`, `--budget SECONDS` (start no new page after this time), `--page-seconds N` (time limit for one page; the summary counts the pages that it cut), `--state-styles K` (the attribute, app, and per-element state tests use `K` of the styles, a different set on each page; default all). Exit status 3 means that pages are left or cut. `--mutate 'STYLE::REGEX::TEXT'` changes the new CSS of one style and `--expect STYLE:PROPERTY` then passes only when the guard reports that property for that style and no other style; use them to prove that the guard sees a rule. The guard cannot see values in the middle of a transition or combinations of two states, and it compares `::selection` rules as text only (`getComputedStyle` does not report them). In WebKit it does not compare the parts below an ancestor that has no box (`display: none`), because WebKit reports old styles there; Chromium and Firefox compare them. The first read of a state compares a 53-bit hash of each style; the second read compares the text.
- `-components` selects component files (default: the components in `-groups`, default `tools/gen/groups.tsv`). `-physical` keeps physical classes. `-parts FILE` also writes the parts, every source class of each component, and the kit selectors of each named group (`group/<name>`) as JSON for `tools/parity`. `go run ./tools/gen utilities -src DIR -content FILE -out FILE` compiles the Tailwind classes in `FILE` with the same theme.
- With `-dir .`, the demo server also serves `/test/spike/index.html` (shadcn docs examples for button, card, field, dialog, dropdown menu with `clanker-ui.css` and `clanker-ui.js`) and `/test/spike/*.css`. The embedded server does not. `test/spike_test.py` checks this page.

### Parity with shadcn

`tools/parity` measures how close the generated CSS is to shadcn: the docs previews of `https://ui.shadcn.com/docs/components/base/<name>`, and the example pages `<name>-example` in a reference app, a real shadcn install of each style. It needs the network and the Tailwind CLI, so it is not part of `test/run.py`.

```sh
uv run --no-project python -I tools/parity/refapp.py --src "$SHADCN_SRC" --out "<ref>" --styles nova,luma
uv run --no-project --with playwright python -I tools/parity/parity.py --src "$SHADCN_SRC" --out "<dir>" --ref "<ref>"
uv run --no-project python -I tools/parity/report.py "<dir>"
uv run --no-project python -I tools/parity/report.py "<dir>" --style rhea
uv run --no-project --with playwright python -I tools/parity/parity.py --src "$SHADCN_SRC" --out "<dir>" --page-style luma --ref "<ref>"
uv run --no-project python -I tools/parity/report.py "<dir>" --style luma
uv run --no-project --with playwright python -I tools/parity/selftest.py
```

- For each component page, it loads the live page (Arial forced), opens each "View Code" block, and copies the DOM of each preview, and of each popup that a trigger opens (click; hover for tooltip, hover card, and navigation menu; right click for context menu). A dialog, alert dialog, or sheet content, and the drawer viewport (the Base UI drawer has viewport and popup wrappers), becomes a modal `<dialog>`; the overlay is its `::backdrop` (the generator writes `drawer-overlay` rules as `[data-slot="drawer-viewport"]::backdrop`). A page without previews (sidebar) uses its `/view/` frames. The tool reads the example sources at the pin from GitHub (`apps/v4/examples/base/*.tsx` and `apps/v4/registry/bases/base/{examples,components}/*.tsx`, blob hash checked against `tree.json`), and the docs-site components that an example imports from `@/components/` (`apps/v4/components/<name>.tsx`: `markdown`, `message-animated`); their classes count as classes of that example. A `data-slot` on a component that is no kit part (`<Streamdown data-slot="markdown">`) may not reach the DOM, so its classes also count for elements without a slot.
- Some docs examples import another shadcn style (`@/styles/base-rhea/ui/bubble`). Some define their own copy of a component (`calendar-hijri` has its own `Calendar`, style `own`). The tool finds the example of each preview by the function name in its "View Code" block and reads its source. A preview in a ported style (`files.styles` of the catalog: Nova, Rhea) is measured against the generated CSS of that style (`tools/gen -style <name>`): each copied page loads the style of most of its previews, and its totals are in `styles.<name>` of `<component>.json` (`report.py --style <name>`). A preview in a style that the kit does not have, or in another style than the rest of its page (`nova@rhea`: the Nova RTL code block on the Rhea page), is measured, but it is not in any totals; `<component>.json` lists it in `other_style`. For a page with non-Nova previews, the tool also measures the Nova example page `/preview/base/<name>-example?style=nova` (the shadcn create preview; each `[data-slot="example"]` is one preview) and counts it. With `--ref`, that page comes from the Nova reference app (a real install). Without it, the live page loads the Nova rules in `@layer base`, so a class of the part beats a Nova class of a later `cn-*` marker, where `tailwind-merge` keeps the Nova class.
- Only the generated CSS styles a part. An element with a `data-slot` keeps only the classes that its example passes via `className`: the longest run of its classes (at the end, or elsewhere after a Base UI `render` merge) that the `className` of a JSX element of that part in the pinned example file of its preview has (string literals, also through a `const` string such as `itemClassName`). The JSX element is of that part when its tag is the part function (`CardHeader`, also a `map.tsv` slot), it has that `data-slot`, or it is the `render` element of that part; other class props (`classNames`, `modifiersClassNames`, `containerClassName`) count for every part of that component. Class attributes of wrappers (`Example`) and other parts do not count. Other code blocks of the page (changelog, component source) are not read. A popup uses the example of the preview that opened it. All other classes go, also every class of the component definition; a preview whose example the tool does not find keeps only classes that are not in the source. An element without a `data-slot` inside a component also keeps classes that are not in the component source. The kit utility `sr-only` always stays (kit markup uses it). Layout elements of the example outside components keep their classes, also when they have a `data-slot` that is no kit part (`example`); they are not measured. The tool sets `data-variant`, `data-size`, part attributes, and kit slots from the live classes (a `cn-<part>-<key>-<value>` marker sets `data-<key>`; a `cn-*` marker of a part of another component that is not in the part's own definition, or classes that a part of another component explains better than the part's own classes, make the element that part with its own part as a boolean attribute, as in `Parts that are other components`; a `data-slot="button"` element keeps its slot; the own classes include the contextual parts whose context the element is in, so a dialog close button in `dialog-content` stays a dialog close); a layout element matches a part without `data-slot` of the page component only with all its classes, compiles the kept classes with the same theme (a named group of a part, as in `group-data-[swipe-axis=x]/drawer-popup:size-full`, also matches the kit selector of that part, like the generated CSS), and shows the copy with the generated CSS.
- The copy gets the live `:root` and `.dark` token values of ui.shadcn.com (its `globals.css`), because the kit defaults are the `neutral` theme. Theme classes of an example (`theme-blue`) are copied as token values.
- It compares the computed styles (96 properties, `::before`, `::after`, `::backdrop`) of every part in light and dark: at rest, disabled, open, and with hover, press, and keyboard focus on up to 8 controls per page. The state attributes that Base UI sets during an interaction (`data-highlighted`, ...) are copied to the copy, so it measures the CSS, not the JavaScript. Before each read, running CSS transitions finish, so both sides show the end state. Infinite animations are paused at time 0 on both sides, and a live carousel autoplay is stopped (like a user interaction), and the tool waits until the slide transform stops changing before it copies the page. Before each state the copy gets all live attributes of that moment (and loses the state attributes, such as `disabled` or `data-open`, that the live element does not have), not only the change. A focus pair is skipped when Base UI moved the live focus to another element. Outline width, offset, and color are compared only when one side draws an outline; the offsets of `sr-only` elements are not compared. Popups and `/view/` roots get `color: CanvasText`, like the live body, which has no color rule. Next.js images load from ui.shadcn.com. The live root attributes that the DOM does not render are added (`data-caption-layout` on a calendar with dropdowns, `data-orientation` on a vertical carousel). The chart is not measured (the kit has its own chart). A part without a `data-slot` is named by its nearest slotted ancestor (`svg in dropdown-menu-item`).
- Same value: px 0.5; `s` and `ms` exact; other numbers 0.01 (opacity, aspect ratio, font weight, `matrix()` scale); `matrix()` translation 0.5 px; colors CIEDE2000 0.5 or less, over white and over black, alpha 0.01 (white and `oklch(0.985 0 0)` differ). `text-align: start` is `left`. The live input-otp container (`data-input-otp-container`) gets the `input-otp` slot, like kit markup. Radii of 1e4 px and more are equal. Transforms of spinning elements and the offsets of positioners are not compared.
- Output: `<dir>/<component>.json` with equal parts, equal (part, state, theme) pairs (elements visible on one side or both), values that are not at their initial value (`all: initial`) on one side or both, all values, pairs by state, every differing part with its states and properties, the top differences, `kept_source` (example classes that are also source classes; `report.py` lists them), `unpinned` (removed classes that are not in the pinned source: upstream is newer than the pin, or an example class that the tool did not find), `other_style` and `nova_page`, and `site` (Vercel deployment id, ETag, date). Also `<component>.rows.json` (every difference), `<component>.pairs.json`, and `<dir>/pages/<component>/` (the copied pages). `parity.py --recompare <dir>` applies changed rules to the stored rows without a browser.
- Limit: example classes compile into a layer above the component rules. In shadcn, `tailwind-merge` keeps a part variant (`in-data-[slot=...]:p-0`, `dark:hover:`) next to a plain example class, and the variant wins; in the copy the example class wins (item, collapsible, sidebar menu button). These differences are in `known.tsv` with the key T7.
- `report.py` prints the totals, one line per component, every differing part, and the kept source classes. The default mode checks only the tool: it exits 1 when a component failed or when the directory has no component result. There is no `masked` check any more: each part takes classes only from the class sets of its own JSX elements, so it cannot keep a class from another element, and the drop self-tests prove that a part without its rules differs. `--strict` is the CSS gate: it also exits 1 when a (part, property) differs in more pairs than the reviewed list `tools/parity/known.tsv` allows (`component`, `part`, `property`, pairs, cause, tab-separated; the first word of the cause is a key of the table below), so a listed part cannot get worse, when a component has no measured part, or when a cause key of `known.tsv` is not in the table below (`--causes`, default this file); it lists entries that no longer differ. `--style <name>` reports and gates the previews of that style with `known-<name>.tsv` (Rhea: `tools/parity/known-rhea.tsv`; the styles measured with `--page-style`: `known-luma.tsv`, `known-lyra.tsv`, ...). `--write-known FILE` writes the differences of a run in that format; a new entry gets the cause `to check`, which `--strict` does not accept until you give it a key.

  Cause keys of `known.tsv`: R the reference page, P positioning or state that JavaScript sets, U upstream shadcn or the docs site, T a known limit of the tool, K a kit difference with an open issue, C a candidate that is not explained yet. Add a key here before you use it.

  | Key | Cause |
  | --- | --- |
  | P2 | The Base UI positioner element (`isolate z-50`). The kit uses the top layer and has no positioner. |

### Behavior parity with shadcn

The same scripted user actions run on the live shadcn page and on our page in the same engine, and the tool compares what a user can observe. The live run records reference files once per shadcn pin (network). The `behavior` module of `test/run.py` compares our pages with them (offline).

```sh
uv run --no-project --with playwright python -I tools/behavior record --only tooltip,select
DIR=. ADDR=127.0.0.1:8110 go run .
uv run --no-project --with playwright python -I tools/behavior gate --base-url http://127.0.0.1:8110 --out "<dir>"
uv run --no-project --with playwright python -I tools/behavior gate --quick --base-url http://127.0.0.1:8110 --out "<dir>"
uv run --no-project --with playwright python -I tools/behavior status
```

- Files: `test/behavior/scenarios/<component>.json` (the actions), `test/behavior/golden/<component>.json` (the references), `test/behavior/fixtures/<component>.html` (our page: kit markup, the same items, labels, and options as the first shadcn example; `fixture.css` holds the example layout classes and forces Arial on our side; a focusable element before and after the example stands for the rest of the docs page, so Tab can leave the component). The server serves the fixtures only with `DIR=.`.
- `record` opens `https://ui.shadcn.com/docs/components/base/<page>`, waits for React, forces Arial, and runs the scenario on the first `[data-slot=preview]` (`preview` selects another one). A docs example in another style than Nova (drawer: `base-rhea`) uses the Nova preview page instead (`url`, `root`). It lets the page load only `ui.shadcn.com` and writes the other hosts to `blocked_hosts`. The clock is pinned as in `test/run.py`, but the docs pages are prerendered, so content made at build time can keep the build date (the calendar shows its build day as today in Chromium and Firefox, and the pinned day in WebKit). A scenario with `dates` stores the dates the live page shows, and the check copies them to the fixture (`data-today`, `data-value`). With `dates.clock` the record first reads the prerendered day (the element with `data-today="true"` and its `data-day`) and pins the page clock to that day, so React state after hydration and every engine agree with the prerendered page. Options: `--only`, `--engines` (default all three), `--widths` (default `1280,390`), `--reduced-motion`, `--check` (record two times and keep a run only when both agree on broken and visible differences and no CSS animation paints in only one frame, which shows a busy page; the React render time of click and key steps is not compared). A golden file has the scenario hash, the shadcn pin of `tools/gen`, the `@base-ui/react` version of `apps/v4/package.json` at that pin (read from `raw.githubusercontent.com`), the live deploy id (`data-dpl-id`), the URL, the date, and one run per engine and width. A changed scenario needs a new record; the check fails until then. `status` lists the references to record again: a changed scenario, a new pin, a new `@base-ui/react` on shadcn `main`, or a new live deploy. The weekly sync records again when `status` lists one. `stamp` adds the deploy id and the Base UI version to references that have none.
- The check skips dark (behavior does not depend on the theme) and each engine, width, or mode without a reference. It fails on a broken or visible difference that is not in the scenario's `allowed` list; minor differences are reported, not failing. It writes `<out>/behavior/<run>/<component>.json` with the first divergent step: later differences can follow from it. `report` writes `<out>/behavior-report.md`: pass and fail per engine and width, then each difference by component and step, with a class (focus, keyboard, state, ARIA, dismiss, timing, geometry) and a severity (broken, visible, minor).
- `gate` runs `test/run.py --only behavior --themes light --jobs <engines>` (one process per engine, about a third of the time of one process), then writes the report. The run log is `<out>/gate.log`. `--queue <script>` (or `BEHAVIOR_QUEUE`) runs `test/run.py` through a shared queue. `--quick` runs Chromium and WebKit at 1280 only (about a third of the checks; it misses Firefox-only focus rings and 390 px geometry). Use the full gate before a merge.
- `drift --out <dir>` finds upstream behavior changes. It records the live pages again (`--only`, `--engines`, `--widths` as in `record`), compares each run with its reference, and does not change `test/behavior/golden/`. A run with a difference is recorded a second time. Drift is a broken or visible difference in both records; a difference in one record is noise and does not fail. As in `record --check`, the React render time of click and key steps is not compared, and timing is not compared on a busy page. The `allowed` entries of a scenario do not apply, except entries with `platforms` (the references are recorded on macOS). A scenario that changed after its record, or a run whose live page shows other dates (the calendar build day), is `stale`, not drift. A run that fails in both records is drift (the scenario no longer fits the live page), but when more than 10 runs fail, the site or the network failed: they get the status `error`. Runs with the same `<dir>` add up (`<dir>/components/<component>.json`, `<dir>/slices.json`), so a long check can run in slices (`--only`, `--engines`, `--widths`); a new check needs a new directory. It writes `<dir>/drift.md` and `<dir>/drift.json` for all slices (per component: status and, per run, the step, the recorded value, and the live value; for drift also an issue title, marker, fingerprint, and body) and exits 1 on drift and 2 on `error` or when the live site does not answer (then without a report). `--merge <dir>...` records nothing: it adds the results of other directories to `<dir>` and writes the report. `.github/workflows/drift.yml` runs it every Monday, on `workflow_dispatch`, and on a pull request with the label `drift-ci`: one macOS job per engine (the references are recorded on macOS; Linux font metrics move some geometry by a few pixels), then a `report` job that merges the results. Except on a pull request, for each drifting component it updates the open issue with the marker `<!-- behavior-drift:<component> -->`, or opens the issue `behavior drift: <component>`; a closed issue with the same fingerprint gets no new issue. It closes no issue.
- Before the first step, both pages put the anchor part 300 px from the top of the viewport, and our page moves the fixture to the same x as the live page. After each step the tool records: the focused element (role and accessible name from the Playwright ARIA snapshot, `data-slot` or the part attribute of [Parts that are other components](README.md#parts-that-are-other-components-aschild), `:focus-visible`, and a painted outline or ring), `aria-activedescendant`, the `data-highlighted` item, the state attributes and ARIA attributes of each part, the ARIA snapshot of the component and of each open popup, the side, align, and offset of each popup against its anchor, scroll lock on `html` and `body`, the direction of the page scroll (not compared when focus is on, or comes from, a page element outside the component), and the values of the form controls (hidden inputs included). A step with `motion` samples its parts in the paint phase and records the open and close delay (input event to DOM change), the CSS animations and transitions (duration, delay, easing), the painted start and end when no CSS animation runs, and the end opacity and size.
- Internal DOM is not compared: positioners, portals, wrappers, where a popup is in the document, the focus guards of the Base UI positioning library (Safari gives them `role=button`; the ARIA snapshot hides them), and wrappers around a popup that add no text or control (the root tree leaves out the Base UI popup `<nav>` of the navigation menu). `aria-hidden` on a part is compared only through "hidden from assistive tech", so it does not matter if the part or a parent has it. `data-state="open"` is the same as `data-open`, `data-popup-open`, and `data-panel-open`; `checked`, `on`, and `active` work the same way. Tolerances: delays and painted times 20 ms plus two frames (34 ms: React on the live page commits a frame later, and the paint sampler adds one frame), animation durations 20 ms, geometry 1 px, opacity 0.02. For a click or key action, a delay or painted time counts only when ours is later than shadcn plus the tolerance (React on the live page needs up to about 200 ms under load). A transition counts as an animation only when the part moves in more than one painted frame.
- Allowed by design (the kit keeps its better ARIA): tooltip `role=tooltip` and `aria-describedby`, names on the resizable handles and the combobox trigger, carousel slide labels, the calendar navigation name, and a command `aria-activedescendant` that points at the selected item (cmdk can keep a stale value). The command input has the name "Command menu". The combobox keeps its input addon and trigger button in the ARIA tree while the list is open (Base UI hides the addon with `aria-hidden`, and with it the focusable button). The drawer keeps the native `<dialog>` as the dialog and puts no role on the popup. Live defects that the kit does not copy: the calendar keeps focus on the day after Enter or a click on a day (the live page replaces the day buttons and focus falls to the body); a cancelled resizable touch swipe does not set the panel to 100 %. The select (steps 8, 11, and 14: a key closes the list), the radio group (step 14), the dropdown menu (step 10, Escape), and the drawer (step 16, Escape) keep the keyboard focus ring in Firefox (Base UI moves focus after the key event, so Firefox paints no ring); the checked state of the context menu and menubar demo items is not compared after a click (the live demos fix it, the kit item changes as in an app). An `allowed` entry covers one attribute on one part: `match` (one difference row), `aria_name` (a name that ours adds where shadcn has none, for one role), or `aria_role` (an extra role on our side). Each `reason` says why the difference is correct; reasons are not in the scenario hash.
- Add a scenario: copy the first shadcn example into `test/behavior/fixtures/<component>.html` with kit markup, write `test/behavior/scenarios/<component>.json`, record it in all engines and widths, and run the module. Change the fixture when the component markup changes.

### Check API

```python
def check_select(t):
    section = t.section("select")
    section.get_by_role("combobox").click()
    t.settle()
    t.shot("open", t.page)
    t.page.keyboard.press("Escape")
```

| Member | Meaning |
| --- | --- |
| `t.page` | Playwright page, already on the demo or on the file's `START` path. |
| `t.docs(path)` | Loads `path` (for example `/docs/components/button`) and fails unless it returns 200 or 304. |
| `t.base_url` | `--base-url` without the trailing `/`. |
| `t.section(id)` | Locator for `#id`, scrolled into view. It becomes the default screenshot target. |
| `t.shot(name=None, target=None)` | With `--shots`: screenshot of `target`, the last section, or the page; a check that used `t.section` and took no shot gets one at the end. Without `--shots`, it does nothing. Do not use it to wait: call `t.settle()`. |
| `t.settle(timeout=2000)` | Waits until finite animations end. Scroll-driven animations and animations of elements that are not rendered (`checkVisibility({ contentVisibilityAuto: true })` is false, for example inside a closed `hidden="until-found"` panel or off-screen `content-visibility: auto` content, where Firefox does not run them) do not count. On a timeout, the check fails with the animations that still run. |
| `t.paint(sample, action, arg=None, ms=800)` | Calls `action()` and returns `sample(arg)` for each painted frame during `ms` milliseconds. `sample` is the source of a JavaScript function. It runs in the paint phase (a `ResizeObserver` on a 1 px probe that changes size each frame), after `requestAnimationFrame` callbacks and layout. Use it for motion checks: a sampler in an early `requestAnimationFrame` reads positions before the kit moves them. |
| `t.a11y()` | Loads `clanker-ui-a11y.css` into the page (after the kit) and waits until it applies. Checks of the optional accessibility layer call it first. |
| `t.expect_console(regex)` | Allows matching console messages for this check only. |
| `t.skip(reason)` | Skips this run, for example `if t.mobile: t.skip("desktop only")`. Console errors and violations collected before the skip still fail the check. |
| `t.engine`, `t.theme`, `t.width`, `t.mobile`, `t.reduced_motion`, `t.rtl` | Current run. |

A `<dialog>` keeps `open` during its exit animation. To find if a popup is visible, use `data-state` or its geometry.

## Release

1. In one pull request: move the `Unreleased` entries of `CHANGELOG.md` to a new section `## X.Y.Z - YYYY-MM-DD`, set `catalogVersion` in `tools/gen/catalog.go` and `version` and the download links in `skills/clanker-ui/SKILL.md` to `X.Y.Z`, and run `go run ./tools/gen dist`.
2. Merge it. Run the full matrix on that commit (`gh workflow run ci.yml --ref main`) and wait until it is green, or use a commit with a green nightly run.
3. Push a signed tag on that commit: `git tag -s vX.Y.Z -m vX.Y.Z && git push origin vX.Y.Z`.

`release.yml` stops before it packs when the tagged commit has no successful full run of `ci.yml` (event `schedule` or `workflow_dispatch`) or is not on `main`, when the tag does not agree with `catalogVersion`, the skill version, or the skill download links, or when `CHANGELOG.md` has no section for the version. That section becomes the release notes. The zip is reproducible: all files get the commit time, a sorted file list, and fixed modes, so a second pack of the tag gives the same `SHA256SUMS`. The release then starts `pages.yml` on the tag. `pages.yml` builds only on a `v*` tag, so the docs site always shows a release.
