Next.js streams a route in chunks, so the page shows up before every request finishes. Linking and Navigating How the App Router streams a route to the browser. nextjs.org (opens in a new tab)

Wrap a slow part of the page in a Suspense boundary and React sends the fallback first. When the data resolves, the finished HTML streams into the same response and replaces the fallback, with no extra request from the browser. <Suspense> Display a fallback until its children have finished loading. react.dev (opens in a new tab) Server Components help here, because their code never ships to the browser. Server Components Components that render ahead of time, on the server. react.dev (opens in a new tab)

A loading.tsx file does the same for a whole route segment. loading.js Show an instant loading state for a route segment. nextjs.org (opens in a new tab) It all runs over chunked transfer encoding, so there is nothing extra to set up. Transfer-Encoding Send a response as a series of chunks. developer.mozilla.org (opens in a new tab)
