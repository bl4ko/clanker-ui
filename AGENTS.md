# AGENTS.md

Instructions for coding agents that change this repository. To use clanker-ui in another project, read [skills/clanker-ui/SKILL.md](skills/clanker-ui/SKILL.md) instead. Humans: [CONTRIBUTING.md](CONTRIBUTING.md). Full tool reference: [DEVELOPMENT.md](DEVELOPMENT.md).

clanker-ui is a dependency-free port of shadcn/ui (Base UI base, Nova style) to plain HTML, CSS, and JavaScript, with a Go standard-library docs and demo server. Components must look and work exactly like the live shadcn site.

## Commands

```sh
go vet ./... && go test ./...
DIR=. ADDR=127.0.0.1:8110 go run .
go run ./tools/gen dist
go run ./tools/gen catalog
go run ./tools/gen catalog -check
uv run --no-project --with playwright python -I test/run.py --base-url http://127.0.0.1:8110 --engines chromium --only g2 -k select --out out/run
uv run --no-project --with playwright python -I tools/behavior gate --quick --base-url http://127.0.0.1:8110 --out out/gate
```

- `DIR=.` serves the working tree, so a change shows without a rebuild; without it the server uses the files embedded at build time. `out/` is ignored by git.
- `test/run.py` flags: `--engines chromium,firefox,webkit`, `--themes light,dark`, `--widths 1280,390`, `--only <test file prefixes>`, `-k <regex>`, `--rtl`, `--reduced-motion`. A check fails on any console error or warning.
- Python tools run with `uv` only. Never use `pip`. JavaScript tools, if a task needs one, use `pnpm` only. The kit itself has no package manager.
- Install Playwright browsers once: `uv run --no-project --with playwright playwright install chromium firefox webkit`.

## Rules for generated files

- After a change to a kit file (`clanker-ui*.css`, `clanker-ui*.js`), run `go run ./tools/gen dist`. `go test` fails when `dist/` or the catalog is old.
- After a change to `README.md`, `tools/gen/groups.tsv`, `tools/gen/examples/`, `docs/nav.json`, or kit slots and events, run `go run ./tools/gen catalog`.
- Change component CSS in the generator or `tools/gen/kit.css`, never in `clanker-ui.css`.
- On a merge conflict in a generated file, take either side and run the generator again.

## Code style

- Almost zero comments in all files. The only allowed comment is the first-line license comment of each kit file. `go test` enforces this for kit, Go, HTML, and docs files.
- The kit has no dependencies, no build step for users, and no network access. The server uses only the Go standard library; esbuild (pinned in `go.mod`) is used only by `tools/gen`.
- Banned in kit, demo, and docs code: `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, string timers, `DOMParser`, `createContextualFragment`, `setHTML`, `setHTMLUnsafe`, `parseHTMLUnsafe`, `srcdoc`, `javascript:` URLs, `setAttribute` with `style`, `srcdoc`, or `on*`, `createElement("script")`, `createElement("style")`, `execCommand`, and dynamic `import()`. HTML has no inline `<script>`, `<style>`, `style`, or `on*` attributes. Build DOM with `h()`, `svg()`, and `icon()`. The README section "Security rules" is the full list; `go test` enforces it.
- Everything works under the strict CSP with `require-trusted-types-for 'script'` (README "Use in a project").
- Match the style of the code around a change. Public API changes need a README update (exports, events, attributes).

## Parity rule

- The reference is the live site: `https://ui.shadcn.com/docs/components/base/<name>` and the Nova preview routes, at the shadcn commit in `tools/gen/main.go` (`shadcnSHA`) and Base UI 1.6.0.
- Find the live behavior first (live bundle, `tools/behavior record`, or a measured probe), then match it. Do not guess values.
- Exception: the kit keeps its better ARIA where the live site is weaker. Each such difference is an `allowed` entry with a reason in `test/behavior/scenarios/<component>.json`.
- `tools/parity` (CSS) and `tools/behavior gate` (behavior) are merge gates for component changes. Both need the network only to record; the gate and the tests run offline.
- Each fix gets a check that fails when only that fix is reverted.
- Test scope: a fix in one component runs that component's tests in Chromium, Firefox, and WebKit, light, at 1280 and 390 px (add dark, `--rtl`, or `--reduced-motion` when the fix touches color, direction, or motion). A shared core change runs its group tests and `foundation`. The full matrix runs before a release.

## Add a component part or attribute

1. Change the kit and the README section of the component (markup fence, attributes, keys, Events table).
2. If the README section has no `html` fence, add or update `tools/gen/examples/<component>.html` (minimal markup; known slots and attributes only).
3. Run `go run ./tools/gen dist` and `go test ./...`. The catalog test checks each example against the parts and attributes.

## Commits and pull requests

- Conventional Commits: `<type>(<scope>): <subject>` with `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, or `perf`. Short subject; details go in the pull request.
- Sign every commit (`git commit -S`). Unsigned commits cannot merge.
- Open a pull request into `main`. Required checks: `ci-result` (tests in all engines) and `gitleaks` (secret scan).
- Never commit secrets, tokens, private keys, or personal data.
